**How to apply (every row):** in the named file and record, find the source ref with that `url` that has a `quote`;
delete `quote` and set `note` to the "New note" cell exactly (a `\|` in a cell is a plain `|`). Where the ref already had a
`note`, the cell already contains it after the paraphrase and "Fetch date unknown.", so nothing is lost. Rows are
listed in file order; the same claim in 8 class guides is 8 rows with the same text. "examples:" means the path is under
`data/schema/examples/packs/aion2/` (not shipped). One record has two quoted refs with the same URL (`asmodian/guide/claims.json`
C11, games.gg): its two rows apply in the order the refs appear in the record. No fact, URL, verdict or label
changes. "Fetch date unknown." follows F9: all of these came from the 2026-10-12 import, read by unrecorded means.

Paraphrase rule I used: the fact in my own words; numbers, levels and in-game names (quest, NPC, item, stat, map) stay
as they are, since they are data or NC's identifiers, not the host's wording.

and the licence named and linked. Today the refs carry the URL only. The page title and the author line can't be
checked: thegameswiki answers our requests with a 429 checkpoint (SOURCES.md, 2026-10-18), so a completed credit
would be built from the URL slug, which is a guess. The ruling's fallback applies: paraphrase. The facts and URLs stay,
and DATA_SOURCES.md keeps its CC BY-NC-SA line for the facts' origin. This also matches SOURCES.md ("facts only, never
wording"). Nothing here is lost: several of these "quotes" read as summaries (the import used WebFetch, which
summarises; F9 found the same), so they may not be verbatim anyway.
