# Support & feedback

**Owner:** Beta Program (Ernesto), for all outside reports, beta or not (Walter, 2026-10-20; LEDGER "Who does what").
Charter: the project's `beta-program/charter.md`.

**Owns:** what users tell us: GitHub issues from *Report a problem*, data corrections and ideas, and reports beta
testers send outside GitHub.

**Standing checklist (once per release, and on request)**
- Read new issues; label `bug` / `data` / `feature` / `ux`; reproduce bugs at the reported version, level and story
  quest; ask for missing details politely (issues are public: never ask for personal information).
- Data corrections go to Gretchen with the reporter's source; bugs and save problems to Gus with a reproduction; look
  and layout to Jane; ideas to Walter as planning inputs (considered at the next minor's planning pass, never queued
  directly).
- Summarise for the owner: counts by label, anything urgent, ideas worth a decision.
- Never promise dates or features in public replies; never mention monetization.
- Beta tester data follows PRIVACY.md "Beta testers": testers are T1, T2 … in public; raw reports are kept only in the
  private repo and deleted on schedule.
