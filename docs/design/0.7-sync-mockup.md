## 1. Where sync lives

**In the footer's save strip, not a new card.** Today that strip holds "Progress is saved in this browser only." and
Export / Import (`#xfer` in `src/index.html`). Sync is about the same thing (where your progress is kept), so it is one
more line there: **`SYNC` + a switch + a status**. Nothing is added to the card grid, so there is no new card style and
nothing moves for a player who never turns it on.

- A panel (today's `.card` shell, full width on a phone, 560 px max on desktop) opens **below the strip** only while a
  step needs more than a line: turning on, joining, showing the code, a confirmation. It closes when the step ends or
  on Cancel. One panel at a time.
- **Basic shows only the label, the switch and the status** (n1, s1, s3–s9). The same panel opens when the
  switch is used; the extra buttons (Sync options, Sync now) are Advanced only.
- **Advanced** adds two small buttons after the status: **Sync now** and **Sync options ▾**. The options list holds
  Show sync code, New sync code, Delete cloud copy, Turn off sync (m1).
- Phone: the strip wraps (text, then the two transfer buttons, then the sync line); controls are 44 px high. Desktop:
  the same elements, 12 px buttons, as the existing strip.
- Reachable by keyboard in reading order; the switch is `role="switch"` with the accessible name "Sync"; a status change
  is announced through `role="status"`; the panel takes focus when it opens and returns it to the switch on close.

## 3. Rules the drawings rely on

- **Code shown once, then on request.** At creation the code appears in t2; "Show sync code" (m2) is allowed on a device
  that syncs (S5 recommendation: losing the code is the bigger risk than someone reading the screen). The code is never
  in an Export file, the *Report a problem* link, a URL or a log (sync.md §1, §3).
- **No new Basic controls beyond the switch.** Delete cloud copy, New sync code and Show sync code are Advanced only;
  Basic can turn sync on, join, see the status and turn it off.
- **Sync runs by itself** (sync.md §1 triggers); "Sync now" only exists in Advanced and is shown in every "on" state.
- **Nothing blocks the page.** The status line is the only thing that changes while a round runs or fails; no toast,
  no modal for `offline`, `conflict`, `error` (they retry on the next trigger and on the `online` event).
- **Ask before anything is lost:** `ask` (j3), New sync code (m3), Delete cloud copy (d1), Turn off (o1). Joining by
  `adopt` asks nothing because the device holds no progress.
- **Artifact (S4):** `dist-artifact` carries none of this (`@web-only`); a1 is today's strip, unchanged.

| `code.saved` | I've saved it |

| `join.button` | Join |
| `join.typo` | That code has a typo. Check the last group. |

| `join.askTitle` | This device already has progress |

## 4a. Design Lead review (2026-10-18, fixes applied)

Design Lead (Jane) reviewed the first drawings and asked for these changes; they are in the frames and texts above.

1. While sync is on, the strip no longer says "this browser only" (false once sync is on): `strip.on`.
2. The confirm field's placeholder was the answer ("FF"); it is now "Last group" (t2).
3. A sync code wraps only between groups, never inside one (code box t2, t3, m2; code field j1, j2). The build keeps
   this rule: each group unbreakable, a break allowed after each hyphen. The join field may be two lines on a phone.
4. M1's caption said five actions; there are four.
5. Advanced order is **Sync now**, then **Sync options ▾** (the common action first), as §1 says.
6. Text fields are 16 px on a phone (iPhone Safari zooms into smaller fields; ux-review-checklist "Phone check").
