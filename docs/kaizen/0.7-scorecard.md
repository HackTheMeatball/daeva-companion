## 7. Blind spots (owner, 1:30 AM ET: "I don't know what I don't know")

- **Usage cost.** No usage % since 6:33 AM ET Oct 18, so the scorecard can't say what 0.7 cost. Only the owner can read
  it (Settings → Usage). New target: one reading at every release.
- **The owner's attention.** 25 owner OKs were recorded in DECISIONS.md in the window, typed in at least 6 different
  threads (C, DECISIONS.md), plus tracker OKs that DECISIONS doesn't hold. Nobody counted this before. New target for
  0.8: ≤ 12 typed OKs, in ≤ 2 threads (K15).
- **Bugs the owner finds after release.** Not counted anywhere yet. New target: count them per release (Coordinator
  tags them), 0 that Player Testing's play missed.
- **Who did what.** All sessions act as one GitHub user, so runs and edits can't be attributed from GitHub. Logs carry
  the attribution; a log row is the only record.
- **Lost failure reasons.** Job logs aren't readable (403), so a build that fails without a comment leaves no cause (K16).
- **Rule growth.** This review adds 4 rules and retires 4. Count kept from now on: rules added vs retired per minor,
  target: never more added than retired.
- **Gates that rely on a convention.** Any Claude session can post the `DESIGN OK` line that auto-merge counts; only
  docs/reviews/README.md stops it (#222, Oct 18 8:51 PM ET). No case so far; checked at 0.8.

## Summary

Building got better: fewer attempts per item, no review CHANGES, 1.5% wasted build minutes, faster builds. The minor took
longer (59 min per item vs 23) because the plan grew from 8 to 22 item PRs and because 540 min passed waiting on owner
OKs typed in the afternoon and evening. K10 missed, and K15 moves every owner OK to one morning batch. The biggest
hidden waste is builds that push but don't open a PR (25% of items, healed silently); K16 logs and root-causes it. Player
Testing's findings show two process gaps, docs that claim more than the app does (K17) and findings with no decision
(K18).
