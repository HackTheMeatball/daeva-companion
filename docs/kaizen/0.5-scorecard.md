## Audit of the workflow

- **Lanes.** No two builds collided on a file in 0.5 (0 conflict rows). The lane that cost time was golden: seven
  items in one serial line (P11 → P3 → P12 → P16), the critical path, behind owner OKs. The build cap (5) was never the
  limit: the most builds in flight at once was set by serial lanes and owner tokens.
- **Model routing.** Opus runs Sonnet would have done: none clear (every Opus build touched golden, core or gen).
  Sonnet runs redone: P7's two Sonnet fix rounds failed the same check and an Opus `@claude` fixed it (107 min PR); P1
  and P2 Blocked were spec and token causes, not model. So the build routing holds; fix round 2 is the weak step.
- **Redone runs.** Causes: the 1 h token (P6), GraphQL denials (release), owner token not recorded (P2), a spec file
  gap (P1), a stale guard already fixed on main (P16 round 1), a duplicate kickoff (P10). Each but the token has a
  rule since (#114 "Spec commands", "Owner tokens", the Ownership check, #226).
- **Idle time on the critical path.** P9 waited 4 h for its research gate (not-queued), P15 2 h; the phone OK held 11
  items 4 h 48 min.
- **Handoffs.** Tracker sync noticed builds late nine times; the root cause (only Kickoff knows a build started, and
  Actions can't write the tracker) is still open. Restart's schedule ran three times on Oct 17, so the health check
  re-checks failed attempts itself.
- **Owner waits.** Both were relay problems: a "yes" through the relay didn't count until typed into DECISIONS, and an
  owner question sat 3.5 h without a To-do. The answer itself took 2 min once asked.
